## 一、优先级总表

按「用户明确要的 > 用户抱怨的 > 业界标配 > 锦上添花」排序。

### P0 —— 用户明确提的三件事（必须先做）

| # | 功能 | 依据 | 工作量 |
|---|---|---|---|
| 1 | **时间线（timeline）** | 用户："不知道这个时间概念" | R7 已给完整设计（566 行） |
| 2 | **AB 区间标记** | 用户："标定 AB 之间脉冲数、AB 之间的时间" | R7 + R2（DSView 光标系统） |
| 3 | **区间统计** | 用户："占空比啥的数据" | R7 第 3 节 + R10 的 measure 扩展 |

**这三件事 R7 已经写成可照抄的设计**：
- 轴高 `AXIS_H = 28`，`bandH = (H - 28) / 8`
- 刻度算法：1/2/5×10ⁿ 取整，每 100px 一个主刻度
- 时间原点：**从采集起点算 0**（不从视图左端，理由：缩放时标签值稳定）
- AB 光标：任意多个、吸附到边沿、删除后自动重编号（抄 DSView）
- 测量面板分四组：鼠标实时 / 光标距离 / 边沿计数 / 光标列表（抄 DSView MeasureDock）

### P1 —— 用户抱怨"功能太少"的直接回应

| # | 功能 | 依据 | 工作量 |
|---|---|---|---|
| 4 | **加 5 个新解码器**（1-Wire/PWM/I2S/Manchester/DMX512） | R4：这 5 个都是「低难度」，onewire_link 参考实现仅 347 行 | 每个约 150~250 行 |
| 5 | **解码器自声明参数**（选项 schema） | R4：我们缺的 7 项机制之一 | 改 `decoder_base` + 前端表单生成 |
| 6 | **区间解码**（只解 AB 之间） | R10 缺口 #1：现在解全量白算 99% | 后端加 `window` 参数 |
| 7 | **解码结果分页** | R10 缺口 #2：3 万事件传 3.6MB，前端只显示 500 | 加 `limit/offset` |

### P2 —— 体验层（用户会立刻感觉到）

### P3 —— 扩展性

| # | 功能 | 依据 |
|---|---|---|

### 明确不做（硬件限制，有依据）

| 项 | 依据 |
|---|---|
| **硬件触发** | R6：libsigrok 的触发是 `soft-trigger.c`，FX2 固件不支持硬件触发；我们的协议也没逆出触发寄存器 |
| **模拟通道** | R6：0925:3881 没有 ADC，纯数字 8 通道 |
| **>8 通道 / >24MHz** | 硬件规格 |
| **USB 全速抓包解码** | 采样率不够（USB FS 12Mbps，逻辑分析仪带宽受限） |
| **CAN FD** | 需要更高采样率和不同帧格式，非不能做但优先级低 |

## 二、P0 的详细落地步骤

R7 已经写到伪代码级别，这里只列实现顺序。

### 阶段 1：时间线（约 2 小时）

1. 布局改造：`AXIS_H = 28`，`bandH = (H - 28) / 8`
2. 实现 `niceStep(raw)` —— 1/2/5×10ⁿ 取整
3. 实现 `buildTicks(startSample, span, rate, plotW)` —— 返回主/次刻度
4. 实现 `drawTimeline(...)` —— 主刻度带标签，次刻度 6px 短线
5. 标签防重叠：跳过策略（间距不足时隔一个保留）
6. 边界裁剪：最左左对齐，最右右对齐，中间居中

**验收标准（R7 给的）**：
- 任意缩放级别下，相邻标签像素间距 ≥ 标签宽度 + 8px
- 单位在 ns/µs/ms/s 之间正确切换
- 缩放时同一时刻的标签值不变（原点固定）

### 阶段 2：AB 标记（约 3 小时）

1. 数据结构 `markers = {a, b, mode}`
2. 交互状态机：工具栏按钮进入放置模式 → 点击放 A → 再点放 B
3. 拖动调整：抓住线拖动
4. 吸附：距边沿 < 阈值（建议 `max(1, plotW/span * 3)` 像素对应的样本数）时吸附
5. 视觉：A 绿色 / B 蓝色（与红色光标 `#ff7b72` 区分），区间半透明填充
6. 读数显示：状态栏 + 画布浮动标签

**冲突处理**（R7 列了 8 条，必须先定）：
- 左键放光标 vs 左键放标记 → **用模式切换**（工具栏按钮），模式内左键只放标记
- 缩放时标记位置 → 按样本索引保持，不随像素走
- 区间移出视图 → 状态栏仍显示数值，画布不画

### 阶段 3：区间统计（约 2 小时）

1. 前端本地算（R7 建议：已有 `data`，不用等网络）
2. 统计项：脉冲数、边沿数、高/低电平样本数、占空比、最短/最长/平均脉宽、频率
3. **脉冲数的精确定义**（R7 特别强调）：
   - 推荐**数上升沿**（`0→1` 的次数）
   - 区间从高电平中间开始时，第一个不完整脉冲**算**（因为上升沿在区间外不算，所以自然排除）
4. 显示：侧栏新增一块「区间测量」，与现有「全量测量」并列

**性能**：4800 万样本区间统计 < 200ms（numpy 风格单次扫描）

## 三、关键数据速查

### 渲染性能（实测）

| 实现 | 4800 万样本/1200 列 |
|---|---|
| 旧：逐样本 for 循环 | **44.9 ms** |
| 逐通道 min/max ×8 | 53.5 ms |
| **新：Uint32 批量 + 全 8 通道** | **6.2 ms** |
| 跳步降采样（段 B 用） | 0.07 ms |

### 解码器生态

- sigrok 共 **132 个**解码器（GitHub API 实测）
- 我们现有 4 个（UART/I2C/SPI/CAN）
- Top 5 值得加：1-Wire、PWM、I2S、Manchester、DMX512（**都是低难度**）

### 后端缺口（R10 列了 10 条，最要紧的三条）

1. `decode` 吃全量 blob → 加 `window` 参数
2. `decode` 无分页 → 3 万事件传 3.6MB
3. 409 不细分原因 → 加 `code: BUSY/OCCUPIED/NOT_READY/NO_DEVICE`

## 四、建议的执行顺序

```
第一批（P0 三件）
  ├─ 时间线        ← 独立，可先做
  ├─ AB 标记       ← 依赖时间线的坐标体系
  └─ 区间统计      ← 依赖 AB

第二批（P1 解码器）
  ├─ 解码器参数自声明（地基，先做）

第三批（P2 体验）
  ├─ 光标吸附
  ├─ 鼠标悬停测量
  └─ 导航条

第四批（P3 扩展）
  └─ 按需
```

## 五、诚实的风险提示

| 风险 | 说明 |
|---|---|
| **R7 是设计不是实现** | 566 行设计文档质量高，但落地时会有设计没覆盖的边界（如极小 span 时轴标签全挤在一起） |
| **R3 的数据可信度** | support.saleae.com 全部 302 到新域名，执行手抓了 20 页但严格说不是原域名。功能描述可信，具体交互细节需实测官方软件确认 |
| **R5 国产软件资料薄** | KingstVIS 手册 PDF 未逐页核对，部分结论是「界面常识」推断 |
| **解码器工作量被低估可能** | R4 的难度估计基于协议标准，实际写代码时 CRC/状态机会更麻烦 |
| **硬件触发彻底没戏** | R6 查了 libsigrok 源码确认是软件触发；除非逆出 FX2 固件的触发寄存器，否则只能软件触发 |
