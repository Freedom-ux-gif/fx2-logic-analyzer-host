# Analyzer SDK · ABI 复原说明

## 这是什么

`01_sdk/` 保存的是 Analyzer SDK 的 **C++ ABI 复原说明**，目的是理解原厂上位机里的解码插件是如何被加载和调用的。

原厂上位机通过一组插件 DLL 来扩展协议解码能力（I2C、SPI、UART 等）。每一种解码器都是一个独立的 DLL，上位机按约定把数据交给它、再取回解码结果。我们整理这些 ABI 信息，是为了搞清楚这套加载机制的接口边界——从而在为将来实现**我们自己的解码插件**时，有一份可参考的接口约定。

> 本目录只保留我们自己整理的 ABI 说明文档。原始导出表 dump（exports_analyzer.json / exports_plugins.json）未随仓库分发——它们是原厂 DLL 的直接提取物。
>
> 本目录只包含原创的整理与说明，不包含任何原厂程序的二进制、导出表原始数据或逐字反汇编输出。

## 三个 C 入口约定

插件 DLL 统一暴露三个 C 入口，这是加载机制的核心：

| 入口 | 作用 |
|---|---|
| `CreateAnalyzer` | 创建并返回一个 `Analyzer*` 实例 |
| `DestroyAnalyzer(Analyzer*)` | 销毁由 `CreateAnalyzer` 创建的实例 |
| `GetAnalyzerName()` | 返回插件名称字符串（`const char*`） |

上位机只要在运行时按名字找到这三个函数，就能完成插件的加载、实例化与卸载，无需在编译期知道插件的 C++ 类型。这是典型的"以 C 接口封装 C++ 实现"的插件模式。

## 这些信息有什么用

整理这套 ABI 的用途，不是复制原厂插件，而是为**互操作**提供参考：

1. **理解插件架构**：看清上位机与解码器之间的职责边界——谁管理采样数据、谁产生解码结果、结果如何回传。
2. **接口参考**：为将来实现自己的解码插件提供一份入口与类结构的清单。
3. **方法学示范**：展示如何在没有 RTTI、没有源码的情况下，仅凭导出名整理出一套可用的接口约定，并明确区分"已确认"与"按名推断"。

## 本文与节选文档的关系

本 `README.md` 是概览。`analyzer_abi.md` 是从完整文档节选出来的接口索引，内容是符号名与接口约定的整理，只保留了 ABI 总览、导出分类、三个 C 入口和关键类结构的开头部分。

完整索引（原文约 68 KB、272 个符号的全量表格）**未随仓库分发**：它是对原厂 DLL 导出表的直接整理，属于原厂程序的衍生物。节选文档已删除所有绝对地址与 RVA 列，只保留不含地址信息的接口描述。

需要继续深挖插件架构的读者，应在合法获得原厂软件的前提下自行分析；本目录不提供原厂二进制、导出表原始数据或逐字反汇编。
