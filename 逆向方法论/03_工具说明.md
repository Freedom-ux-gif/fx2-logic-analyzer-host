# 工具说明

> **重要：本节描述的工具脚本，均未随本仓库分发。**
>
> 原文写于项目内部，那时这些脚本就在 `tools/` 目录里。制作公开发布版时，`tools/` 整个目录被排除——因为它同时存放了原厂程序的内存镜像。这里保留**功能说明与输出规格**，是因为它们记录了「怎么读一个加密的 PE」这套方法，你可以按说明自己实现（每个工具逻辑都很直白，H3 第 2 章给出了关键骨架）。**请不要再尝试从本仓库里找这些 .py 文件。**

这套方法用于「读取与分析」，共同原则是**只读目标，不改目标程序**。

> `dump_rpm.py` 使用 ReadProcessMemory 而非注入，避免修改运行中进程。
>
> 这些思路可以自由使用，但**使用它们分析他人软件的法律后果由使用者自行承担**。

## 工具一览（仅说明，脚本不在本仓库）

| 工具 | 用途 | 参考命令形态 |
|---|---|---|
| `dump_rpm.py` | 内存 dump。仅用 ReadProcessMemory 抓取运行中进程已解密的镜像，保留原始 PE 段布局；不注入、不改进程 | `python -I dump_rpm.py --out <镜像>.bin --wait 8` |
| `intel.py` | 字符串情报。从已解密镜像里挖掘源文件名、类名、日志消息等元信息——协议知识往往藏在这里 | `python -I intel.py <镜像> --classes --strings PATTERN` |
| `scan_field.py` | 指令扫描。逐字节重试地扫描 `.text` 段，找访问指定结构体偏移的指令，覆盖率高 | `python -I scan_field.py 0xb8` |
| `mem_vs_file.py` | 熵对比。比较内存字节与磁盘字节，判断加密段是否在运行时解密，决定值不值得做内存 dump | `python -I mem_vs_file.py` |
| `find_api.py` | 端口/协议字符串搜寻。找 socket API 的端口、成帧的命令名与协议相关字符串 | `python -I find_api.py` |
| `socket_region.py` | socket 命令区提取。读取派发区附近的可打印字符串并聚类，还原命令名 | `python -I socket_region.py` |
| `scan.py` | 通用关键词扫描。按一组关键词（如驱动名、VID/PID、库名）在文件里定位上下文 | `python -I scan.py <镜像>` |

命令中的文件名是占位，替换为你自己合法获得的目标镜像路径。`python -I` 是隔离模式，会跳过当前目录的 `sitecustomize.py` 之类注入，避免误加载不可信模块——分析来历不明的文件时这一点很重要。

## 各工具要点

**`dump_rpm.py` —— 不注入的镜像获取。** 基于 frida 的 dump 脚本曾让目标进程崩溃：在同一会话里创建过多脚本导致目标自行退出。改用 ReadProcessMemory 后不需要在目标里执行任何代码，进程保持正常运行。输出保留原始段布局，因此能在反汇编器里按与运行模块相同的地址打开。

**`intel.py` —— 元信息优先。** 磁盘上的原始镜像是加密的，经 `dump_rpm.py` 恢复出的解密镜像才携带真实的 RTTI 字符串、Qt 元对象名、源码路径和日志消息。挖这些信息比直接啃反汇编快得多。

**`scan_field.py` —— 覆盖率的坑。** capstone 的 `disasm()` 生成器遇到第一个无法解码的字节就会静默停止，直接遍历它只能覆盖极少指令。这个脚本逐字节前进并重试，才能达到约 99% 的覆盖率。

**`mem_vs_file.py` —— 先问"运行时会不会解密"。** 通过对比内存与磁盘的若干段字节，判断高熵段是否在运行时被解密。若两者不同，才值得做内存 dump；这一步能避免对静态加密文件做无用功。

**`find_api.py` / `socket_region.py` —— socket API 线索。** 前者在代码里找常见端口号的立即数形式与 socket 相关字符串；后者针对命令派发区做局部字符串提取，因为命令字面量通常与实现代码相邻。

**`scan.py` —— 快速定位。** 用一组预设关键词（如驱动名、厂商标识、库名）在文件里扫一遍，输出每个命中点的上下文，适合起始阶段的粗定位。它不依赖任何第三方库，是最先可以跑起来的工具。

## 典型工作流

这些工具不是孤立的，按下面的顺序搭配使用效率最高：

1. 先用 `mem_vs_file.py` 判断目标段是否在运行时解密。若否，静态文件可直接分析；若是，进入下一步。
2. 用 `dump_rpm.py` 抓取运行中的解密镜像，得到可供静态分析的文件。
3. 用 `intel.py` 从镜像里挖元信息，先建立"有哪些类、有哪些日志消息"的整体地图。
4. 用 `scan.py` / `find_api.py` / `socket_region.py` 粗定位感兴趣的功能区。
5. 用 `scan_field.py` 对结构体偏移等具体目标做精细扫描，逐步收敛到关键逻辑。
6. 把结论按本项目规格文档的风格写成语义描述，而不是保留逐字指令清单。

这条流程体现了贯穿本项目的两个原则：**元信息优先于反汇编**，以及**只读优先于注入**。前者让你先用最快的手段拿到最多线索，后者让你在拿到线索的同时尽量不惊动目标。

## 使用边界

这些工具的共同点是**只读**：它们读取文件、读取另一个进程的内存、解码指令、统计字节，不向目标写入任何数据，不挂钩函数，不注入代码。这是有意的设计——既能拿到所需信息，又尽量减少对目标进程的干扰和法律风险。

即便如此，工具本身能做什么、你拿它去分析谁，是两回事。请自行确认你对目标软件拥有分析的权利，并遵守所在地区的法律与软件许可条款。本项目不对使用这些工具分析他人软件的行为承担责任。
