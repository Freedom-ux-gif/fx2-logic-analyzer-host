## 0. 三分钟看懂这个项目

本项目是一套 **USB 逻辑分析仪（克隆板 VID:PID = 0x0925:0x3881）** 的反向工程成果。
最终推荐产品是 **网页版（`13_web/`）**：后端 Python 本地 HTTP 服务 + 原生 JS Canvas 前端。

一句话数据流：**设备 → ctypes 读 USB → 落盘 bin → HTTP 传给浏览器 → Canvas 画波形 → Python 解码协议**。

三条主线要分清：

| 线 | 目录 | 状态 |
|---|---|---|
| 采集（拿数据） | `03_host/` + `08_fx2/` | 唯一验证可用 |
| 分析（解码/导出/触发） | `09_app/` + `12_trigger/` | 核心算法 |
| 展示（人机界面） | `13_web/`（推荐）、`10_gui/` + `11_pack/`（备用） | 主产品 / 备份 |

**改动心法**：先按第 1 节定位目录，再按第 2 节判断影响面，然后照第 3 节的配方抄改，最后按第 5 节跑对应测试。
**任何改动都不要跳过测试**——71 个用例全绿是本项目唯一的健康基线。

## 2. 核心代码地图

### 2.1 数据流全景

```
[USB 设备 0x0925:0x3881]
   ↓ EP 0x82（批量读端点）
[03_host/winusb.py]  ctypes 调 WinUsb_ReadPipe
   ↓ bytes
[08_fx2/capture_verified.py]  3 线程并发读（cv.capture_timed）
   ↓ bytes + rate_hz
[13_web/server.py]  save_capture 落盘 + STATE.register 内存元数据（LRU 20）
   ↓ HTTP: GET /api/data/<id> → application/octet-stream
[13_web/static/app.js]  Uint8Array → Waveform.decimate → Canvas draw
   ↓ POST /api/decode {id, protocol, params}
[09_app/decoder_*.py]  解码 → list[DecodeEvent] → JSON → 事件表格 + 三角标记
```

从右往左读是「数据怎么来的」，从左往右读是「改哪一层会影响下游」。
注意：**后端只做采集/解码/落盘，前端只做渲染/交互**；两端的契约就是第 2.2 节列出的 API。

### 3.1 配方 A：加一个新协议解码器（最常做）

下面以新增 `xxx` 协议为例，8 步全部给出可抄代码。假设 RX 信号接到 CH2。

**第 1 步**：复制 `09_app/decoder_uart.py` 为 `09_app/decoder_xxx.py`，改类头与构造：

```python
from decoder_base import DecodeEvent, SampleStream, Decoder
import numpy as np

class XxxDecoder(Decoder):
    name = 'xxx'
    def __init__(self, stream: SampleStream, channel: int = 2, **opts):
        super().__init__(stream, **opts)
        if not (0 <= channel <= 7):
            raise ValueError(f'channel 必须是 0..7，收到 {channel}')  # 非法参数抛中文 ValueError
        self.channel = channel
```

**第 2 步**：照 `decoder_can.py:45` 的 `_edges` 写向量化边沿检测，再在 `decode()` 里逐边沿跑状态机：

```python
    def decode(self) -> list[DecodeEvent]:
        bits = self.stream.channel_bits(self.channel)   # uint8 0/1 数组
        if bits.size < 2:
            return []
        rising = np.flatnonzero((bits[:-1] == 0) & (bits[1:] == 1)) + 1
        events = []
        for e in rising:                       # 逐边沿处理，不逐样本遍历
            s = int(e)
            events.append(DecodeEvent(s, s + 1, 'frame', {'value': 0}))
        return events
```

**第 3 步**：文件末尾加模块级便捷函数（照 `decoder_uart.py:151`）：

```python
def decode_xxx(data: bytes, rate: int, channel: int = 2, **opts) -> list[DecodeEvent]:
    return XxxDecoder(SampleStream(data, rate), channel=channel, **opts).decode()
```

**第 4 步**：在 `09_app/synth.py` 末尾加 `synth_xxx()`，必须走 `pack_channels()` 统一位序（CHn→bitn）：

```python
def synth_xxx(frames: list[int], rate: int, ch: int = 2, spb: int = 8) -> bytes:
    bits: list[int] = []
    for val in frames:
        bits.extend([0] * spb)                      # 起始位（按协议改）
        for k in range(8):                          # 8 数据位，按协议的位序展开
            bits.extend([(val >> k) & 1] * spb)
        bits.extend([1] * spb)                      # 停止位
    return pack_channels({ch: np.asarray(bits, dtype=np.uint8)})  # 唯一位序转换点
```

（`spb` 是每个码元占的样本数；真实协议要按帧结构改电平序列，但**末行 `pack_channels({ch: ...})` 不能改**——它是 CHn→bitn 的唯一转换点。）

## 4. 必须遵守的约定（6 条）

**4.1 `python -I` 与 `sys.path.insert`**：`-I` 隔离模式清空 CWD 和 `PYTHONPATH`，脚本必须自己把目录插进路径。正确写法（见 `09_app/test_decoders.py:16-17`）：

```python
import os, sys
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
```

`server.py:19-22` 的做法是多目录插入：`for _sub in ("03_host","08_fx2","09_app","12_trigger"): sys.path.insert(0, os.path.join(_ROOT, _sub))`。

**4.2 静态资源绝对路径**：页面在 `/` 下，`<script src="/static/app.js">`、`<link href="/static/style.css">` 必须带前导 `/`；写成 `static/app.js` 会解析成 `/static...` 之外的相对路径导致 404。

**4.3 通道映射 CHn→bitn**：本机克隆板实测 `CH0=bit0 … CH7=bit7`（`(val >> n) & 1`），与 sigrok 文档的「CH1=bit7」相反。唯一转换点在 `09_app/synth.py:31,35` 的 `pack_channels()`；解码侧统一调 `stream.channel_bits(ch)`（`decoder_base.py:58`）。ch=8 仅为兼容旧代码按 bit7 处理，新代码一律 0..7。

**4.4 打包时 stdout 为 None 的防护**：`--noconsole` 打包后 `sys.stdout` 是 `None`，直接 `reconfigure` 会崩。`decoder_base.py:32-33` 的正确写法：

```python
if sys.stdout is not None:   # PyInstaller --noconsole 下 sys.stdout 为 None
    sys.stdout.reconfigure(encoding='utf-8', errors='replace')
```

**4.5 单位约定**：`measure_channel`（`server.py:237`）输出的 `min_pulse`/`max_pulse` 是**样本数**，不是秒；`duty`/`high_ratio` 是 **0~1 比例**，`freq` 是 Hz。前端 `app.js:589-594` 先做 `m.min_pulse / rate` 再传给 `fmtTime`，`duty*100` 才显示百分比。直接当秒显示会得到 `1000000.000000 s` 这种离谱值。

**4.6 测试保护**：不许改测试来「通过」，不删除、不跳过失败用例、不降低断言。71 个用例全绿是健康基线；改坏了先修实现，不要用 `skip` 或放宽 `assert`。

## 7. 代码风格

- **前端**：IIFE 包裹 `(function (global) { ... })(window)`（`app.js:2,1152`），无模块系统，`var`/`function` 风格，末尾把对象挂到 `global.LA`（1140-1144）供 selftest 使用。新增内部函数沿用 `var` + 具名 `function`，别混用 ES module。
- **后端**：Python 3.10+ 类型注解，`from __future__ import annotations`；异常统一抛 `ApiError(status, 中文消息)`（62 行），由 `safe_handler` 转 JSON；所有对外错误文案用中文。
- **解码器**：继承 `Decoder`，实现 `decode() -> list[DecodeEvent]`；参数在 `__init__` 校验并抛中文 `ValueError`；边沿检测用 numpy 向量化（`np.flatnonzero` / `np.byte` 位移），逐帧处理只遍历边沿不遍历样本；模块级提供 `decode_xxx()` 便捷函数。
- **测试**：纯标准库 `unittest`（不引 pytest）；合成数据用 `synth.py` 的生成器反证解码正确性；命名 `test_*.py`，用例 `test_数字_描述`。
- **注释**：关键「为什么」要写进注释，尤其是踩过坑的地方（见 `app.js:263-264` 的 LABEL_W、`server.py:570-572` 的达成率分母口径）——这是本项目文档的惯例。

## 8. 已知技术债

| 项 | 现状 | 影响 / 建议 |
|---|---|---|
| 前端无模块系统 | 单文件 1152 行 IIFE，靠全局 `LA` 暴露 | 改动大功能时先读第 2.2 节影响面；不要拆分 `app.js`（会破坏 selftest 的 `LA` 契约） |
| 采样率列表缓存 | `app.js:929-944` 用 `data-sig` 比对才重建下拉 | 无条件重建会冲掉用户选择（踩过），改动 `refreshStatus` 时保留此守卫 |
| 设备占用是头号故障 | `refreshStatus` 里三处分支处理（`app.js:894-924`） | 前端文案做了兜底，后端 `occupied_hint` 也做了翻译；新增状态分支要两处同步 |
| `signal_present` 推断 | 后端 `signal_in_blob`（`server.py:210`）只看相邻字节是否不同 | CH0 未接线会误报「未检测到信号」；提示文案已覆盖，勿删 |
| 事件行上限 | `app.js:649 DECODE_MAX_ROWS = 500`，超出只提示不渲染 | 长采集丢显示但不丢数据；改大前评估 DOM 性能 |
| 采集窗口裁剪 | `server.py:562-566` 按 `hz*seconds` 裁掉读线程多收的 0.2s | 达成率分母必须用 `seconds` 而非 `elapsed`（570-573 行），否则算出 84% 误导用户 |
| 旧版 GUI 与网页版逻辑重复 | `10_gui/`、`11_pack/` 保留完整 tkinter 实现 | 改业务逻辑时两边都要考虑；网页版是主线，旧版仅兼容 |
| 解码分派集中在一处 | `server.py:323 decode_events` 的 if/elif 链 | 协议多起来会变长；新增协议按配方 A 第 6 步插分支，别另起分派入口 |
